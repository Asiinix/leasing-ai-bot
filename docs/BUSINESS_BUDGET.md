# Подбор по финансам бизнеса

Локальный сценарий в чате: `src/features/business-budget/conversation.ts`.
Работает с текстом и расшифровкой существующего голосового ввода. Файлы отчётности не загружает, LLM не вызывает.

## Диалог

Полный пример не показывается в стартовом приветствии чата. Он появляется в первом ответе финансового сценария — после запроса о налогах или нажатия «Подобрать по налогам бизнеса»:

«Налоги 20 млн, выручка 120 млн, расходы 76 млн, обязательств нет, аванс 3 млн».

Можно написать или продиктовать все показатели одним сообщением: если данных достаточно, сразу запускается подбор. Если передана только часть — сохраняем её и спрашиваем только недостающее. Резерв необязателен; при желании можно добавить «Резерв 1,5 млн в месяц». Текст подсказки и рабочий пример находятся в `src/features/business-budget/prompts.ts`; пример проверяется тестом как реальный ввод.

Пошаговый вариант сохраняется:

1. «20 миллионов налогов» → налоги за год по умолчанию.
2. «Выручка 120 млн, расходы 76 млн» → расходы без налогов и действующих кредитных/лизинговых платежей.
3. Уточнение текущих обязательств → «нет», «6 млн» (за год) или «500 тысяч в месяц».
4. Чат показывает свободный остаток, предлагает сохранять 75% на нужды бизнеса и спрашивает сумму аванса. 75% — изменяемое допущение демо, не правило андеррайтинга BCC.
5. «Аванс 3 млн» → бюджет передаётся существующему подбору условий и карточек автомобилей.
6. «Резерв 1 млн в месяц» → пересчёт подбора; «Ещё варианты» → следующая тройка; «Отмена» → обычный подбор по платежу.

## Формула и границы

- Годовой свободный остаток = выручка − операционные расходы − налоги − платежи по текущим обязательствам.
- Если пользователь явно сообщил, что налоги или обязательства уже включены в расходы, повторного вычитания нет.
- Месячный остаток = годовой / 12, с округлением вниз до тенге.
- Резерв по умолчанию = 75% положительного месячного остатка, округление вверх; пользователь может задать свою сумму.
- Максимальный платёж = месячный остаток − резерв.
- Это упрощённая оценка денежных возможностей по словам клиента. Выручка принимается за поступления, расходы — за выплаты; сезонность и изменение оборотного капитала отдельно не моделируются. Результат не называется бухгалтерской или налогооблагаемой прибылью и не является одобрением.
- Из одной суммы всех налогов прибыль не выводится; налоговые ставки для этой формулы не нужны.
- Явные месячные/квартальные показатели переводятся в годовые; без периода — год. Резерв спрашивается и показывается в месяц, аванс — разовая сумма.
- Нулевые налоги/обязательства допустимы; нулевой или отрицательный остаток, резерв не меньше остатка, нулевой аванс не запускают подбор.
- Страхование остаётся отдельным расчётом. Ставки и границы лизинга берутся существующим поиском по модели; сценарий не создаёт тарифов.
- Суммы хранятся только в состоянии открытого чата; в КП/QR финансовые показатели бизнеса не переносятся. После выбора авто используются обычные параметры предложения.

## Проверка

`npm test`, `npm run lint`, `npm run build`.

Сценарий: налоги 20 млн, выручка 120 млн, расходы 76 млн, обязательств нет → 24 млн за год / 2 млн в месяц, резерв 1,5 млн, платёж до 500 тыс. Аванс 3 млн → существующие карточки с условиями в этих ограничениях.

Проверки парсинга/состояния: `tests/business-budget.test.ts`, `tests/business-period.test.ts`. Отдельно проверяются исправления сумм, включённые в расходы налоги/кредиты, отсутствие свободных средств и возврат к обычным сообщениям чата.
