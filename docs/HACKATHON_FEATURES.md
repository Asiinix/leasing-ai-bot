# Фичи для хакатона

Код подготовлен в локальной ветке `feature/hackathon-catalog`, в рабочей копии `work/leasing-hackathon`. Включение фич — локальная операция: команда не создаёт коммиты, не пушит код и не меняет Railway. Сами модули лежат в `src/features/`.

## Названия для быстрого подключения

| Фича                            | Техническое имя       | Что появляется                                                                                                                                                                                                                            |
| ------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Каталог с фиксированными ценами | `fixed-price-catalog` | Каталог всех моделей и продавцов с фото и ценой: шесть цен по сохранённым источникам, остальные — явно обозначенные демо-оценки. Выбор подставляет цену в калькулятор.                                                                    |
| Карточки машин в чате           | `chat-vehicle-cards`  | Автоматические дополнительные варианты под платёж и аванс после ответа по выбранному автомобилю. Переключать режим поиска не нужно. Компактные карточки: три в ряд на широком экране, горизонтальная лента на мобильном. Требует каталог. |

Будущие команды ассистенту:

- «Добавь фичу **Каталог с фиксированными ценами** (`fixed-price-catalog`) и задеплой».
- «Добавь фичу **Карточки машин в чате** (`chat-vehicle-cards`) и задеплой».

Во втором случае подключаются обе фичи. Если целевая ветка ещё не содержит `src/features/` и интеграцию с калькулятором/чатом, сначала перенесите код из подготовленной ветки; один флаг код из другой ветки не загружает. Переносите **весь диапазон коммитов `baseCommit..featureCommit`**, указанный комплектом `outputs/hackathon-features/manifest.json`: первый коммит содержит исходные фичи, следующие — их доработки. Cherry-pick одного первоначального коммита больше недостаточен. Включение флагов не означает публикацию сайта.

Отдельные инструкции комплекта: `outputs/hackathon-features/features/fixed-price-catalog.md` и `outputs/hackathon-features/features/chat-vehicle-cards.md`. У каждой описаны поведение, активация, Railway и проверка. Модули поставляются общим пакетом, а функции включаются независимо; карточки имеют явную зависимость от каталога. После переноса первой фичи тот же пакет повторно не применяется, достаточно нового профиля и отсутствующих доработок кода.

## Локальное включение

Выполняйте команды в корне рабочей копии с подготовленным кодом. Для первого запуска установите зависимости: `npm ci`.

```sh
# Показать только статусы этих фич из .env.local
npm run feature -- list

# Каталог без карточек в чате
npm run feature -- use fixed-price-catalog

# Карточки в чате и каталог — зависимость включается автоматически
npm run feature -- use chat-vehicle-cards

# Базовое приложение, обе фичи выключены
npm run feature -- use none

# Выключить только карточки, оставив каталог
npm run feature -- disable chat-vehicle-cards

# Выключить каталог и зависящие от него карточки
npm run feature -- disable fixed-price-catalog
```

По умолчанию обе фичи выключены: для включения требуется точное значение `true`. Скрипт `scripts/features.mjs` сохраняет остальные переменные, комментарии и формат перевода строк в `.env.local`; значения других переменных в консоль не выводятся. Повторная команда с тем же состоянием не перезаписывает файл. `.env.local` исключён из Git.

Команда `use` устанавливает **оба флага**, независимо от предыдущей демонстрации. Прежние `enable` / `disable` остаются совместимыми: например, `enable fixed-price-catalog` сохраняет уже включённые карточки, поэтому для сценария «только каталог» нужен `use fixed-price-catalog`.

Перезапустите dev-сервер после изменения флагов:

```sh
npm run dev
```

Если порт 3000 занят основной версией, запустите отдельно:

```sh
npm run build:design-system
npx next dev --hostname 127.0.0.1 --port 3003
```

`list` показывает только `.env.local`, а не флаги уже запущенного сервера или опубликованного сайта. Переменные оболочки и `.env.development.local` / `.env.production.local` могут иметь более высокий приоритет; перед демонстрацией убедитесь, что эти два флага не переопределяются там.

## Production-сборка

Имена переменных:

```dotenv
NEXT_PUBLIC_FEATURE_FIXED_PRICE_CATALOG=true
NEXT_PUBLIC_FEATURE_CHAT_VEHICLE_CARDS=true
```

Next.js встраивает `NEXT_PUBLIC_*` в клиентский JavaScript во время `next build`. После переключения фич требуется **новая сборка**; одного перезапуска `next start` недостаточно.

```sh
npm run feature -- use chat-vehicle-cards
npm run build
npm start -- --port 3003
```

В Railway эти переменные следует задать для нужного сервиса **до сборки** и заново развернуть сервис. Локальный скрипт не меняет Railway. Флаги не являются секретами; конфиденциальные данные нельзя размещать в `NEXT_PUBLIC_*`.

Для одного каталога задайте `NEXT_PUBLIC_FEATURE_FIXED_PRICE_CATALOG=true` и `NEXT_PUBLIC_FEATURE_CHAT_VEHICLE_CARDS=false`; для базового приложения оба значения `false`. Всегда задавайте оба значения явно, чтобы ранее включённая фича не осталась активной.

По текущей конфигурации публикация основной версии идёт в Railway-проект `86dfc36d-19a3-47fd-9e0b-96b0d64478fc`, окружение `production`, сервис `leasing-ai-bot`, исходная ветка GitHub `Asiinix/leasing-ai-bot:main`. Перед публикацией сверить привязку. По просьбе «и задеплой» перенести и проверить код, выставить профиль Railway, отправить в main, дождаться сборки нужного SHA и проверить публичный сайт. Сохранить `ANDREY_ORIGIN`, режим Colvir, `PORT` и другие настройки; сервис и ветка `andrey` не изменяются. Одно переключение локального профиля не означает успешный деплой.

## Данные демо

У каждой из **1 036 записей модели/продавца** есть цена для предварительного расчёта:

- **6 `reference`** — сохранённые цены с опубликованным источником, комплектацией и датой проверки **23 сентября 2026 года**.
- **1 030 `estimate`** — **«Ориентировочная демо-цена»**. Она рассчитана по описанным правилам модели/семейства/сегмента и не является прайсом конкретного продавца.

Все автомобили доступны в едином списке с поиском, без переключателя «Все авто / Из прайсов». Выбор любой позиции подставляет её цену в калькулятор. Пользователь может изменить сумму по предложению продавца. Цены и иллюстрации не подтверждают наличие автомобиля. Дополнительный информационный баннер каталога не отображается.

| Марка и модель   | Комплектация | Цена по сохранённому источнику, ₸ |
| ---------------- | ------------ | --------------------------------: |
| Chevrolet Cobalt | Optimum AT   |                         6 490 000 |
| Hyundai Elantra  | Smart        |                        10 590 000 |
| Kia Seltos       | Comfort      |                        12 490 000 |
| Kia Sportage     | Comfort      |                        12 790 000 |
| Hyundai Tucson   | Classic (+)  |                        13 490 000 |
| Hyundai Sonata   | Base         |                        13 990 000 |

Источник, дата и связь шести `reference`-цен с моделью/продавцом хранятся в `docs/roadmap/leasing-demo-car-catalog.json`. Такая цена присоединяется только при совпадении идентификаторов модели и продавца и нормализованных названий марки/модели. Сохранённая цена одной позиции не выдаётся за подтверждённый прайс другой модели или продавца.

Полный ценовой снимок находится в `src/features/fixed-price-catalog/price-snapshot.json`. Правила и резервная оценка новых моделей — `pricing.ts` и `price-rules.ts` в той же папке; методика и источники ориентиров — [docs/pricing/README.md](pricing/README.md).

Происхождение различается явно: `priceKind` — `reference` или `estimate`; `priceMethod` — `published-price`, `model-anchor`, `model-family` или `segment-estimate`; `priceBasis` объясняет основание. У оценок нет выдуманного прайса дилера или даты его проверки: `priceSourceUrl` / `priceCheckedAt` остаются `null`, отдельно указана дата оценки `priceEstimatedAt`. Неизвестные комплектации и модельные годы также не подставляются как факты.

Если API позднее вернёт модель, которой нет в снимке, она получает **детерминированную резервную демо-оценку** с той же явной маркировкой. Новые записи не останутся без цены и не будут молча представлены как подтверждённый дилерский прайс.

## Тарифы и покрытие подбора

Цена есть у всех записей, но возможность показать **ежемесячный платёж** определяется отдельно: нужны реальные условия именно выбранной модели и типа клиента. Матрицы тарифов не копируются между моделями и не генерируются из цены или марки.

- В режиме `COLVIR_MODE=snapshot` используются только реально сохранённые матрицы своей модели; внешние запросы не выполняются.
- В режиме live тарифы запрашиваются пакетно для ограниченного набора кандидатов. Это частичный подбор, а не подтверждение проверки всего справочника за один запрос.
- Если собственный актуальный тариф недоступен, может использоваться только сохранённый тариф этой же модели, с явным обозначением источника `snapshot`.
- Модели без доступных собственных условий не получают выдуманный платёж. Интерфейс сообщает покрытие подбора; количество записей с ценой не равно количеству подтверждённых предложений.

Чат отправляет один POST `/api/vehicle-terms`. В сохранённом снимке есть собственные матрицы 7 моделей; остальные записи явно исключаются из проверки. В live-режиме выбирается до 12 кандидатов, для которых отправляется один пакетный запрос ставок и один запрос лимитов. Каталог кэшируется на 10 минут, успешный пакет условий — на 60 секунд. Интерфейс показывает число автомобилей с проверенными условиями.

Текущая модель исключена из дополнительных предложений: ответ по ней уже дан выше. Поэтому число проверенных альтернатив зависит от выбранной машины (например, при выбранной модели из тарифного snapshot остаётся 6 сохранённых альтернатив). Запрос «Ещё варианты» выдаёт следующую тройку из последнего подбора без повторов и сохраняет бюджет. При изменении бюджета или контекста выполняется новый подбор; старые предложения нельзя применить как актуальные.

Расчёт предварительный, без страхования и комиссий.

## Фотографии и расположение карточек

На широком экране компактные карточки машин расположены **по три в ряд**. На мобильном используется **горизонтальная лента**; её можно листать, сохраняя читаемую ширину карточек.

Подписи и блоки авторства под фотографиями убраны из карточек. Авторы, источники, лицензии и пояснения о том, какая модель изображена на фотографии марки, доступны на отдельной странице по ссылке **«Источники фотографий»** в подвале. При отсутствии или ошибке загрузки фото остаётся заглушка **«Фото уточняется у продавца»**. Изображение другой модели той же марки используется как иллюстрация; фотография не подтверждает точную комплектацию автомобиля.

## Сценарий проверки демонстрации

Следующий список — инструкция для проверки текущей ревизии, не утверждение, что все сценарии уже пройдены.

1. Примените `npm run feature -- use chat-vehicle-cards`, перезапустите dev-сервер либо выполните новую production-сборку.
2. Найдите автомобиль в едином списке каталога и выберите его: цена должна подставиться в калькулятор. Для оценки видна маркировка **«Ориентировочная демо-цена»**; у `reference` доступны источник и дата. Переключателя «Все авто / Из прайсов» и верхнего баннера быть не должно.
3. Откройте помощника и напишите: **«До 300 тысяч в месяц, аванс до 2 млн»**. Переключателя «Выбранное авто / Авто из каталога» нет: после ответа по выбранной машине помощник сам предлагает **«Ещё варианты под ваш бюджет»**. Проверьте покрытие подбора и источник тарифов. Состав предложений зависит от доступных условий; при нехватке данных появляются уточнения.
4. Проверьте три карточки в строке на широком экране и горизонтальную ленту на мобильном. Фото, цена, платёж, аванс, срок и кнопка выбора должны оставаться читаемыми. Под фотографиями нет подписей; сведения об изображениях открываются по ссылке **«Источники фотографий»** в подвале.
5. Выберите автомобиль. Калькулятор должен получить его модель, цену и условия; повторный подбор после изменения бюджета должен блокировать старые предложения.
6. Проверьте новую модель, отсутствующую в ценовом снимке: резервная цена должна иметь маркировку оценки. Отсутствие тарифа не должно создавать фиктивный платёж.
7. Примените `use fixed-price-catalog` и пересоберите: каталог остаётся, автоматических карточек в чате нет. Затем `use none` с новой сборкой: обе дополнительные фичи должны исчезнуть, базовый калькулятор и подбор его условий остаются доступны.

Для воспроизводимого офлайн-сценария можно отдельно задать `COLVIR_MODE=snapshot`; feature-команда эту настройку не меняет.
